# Project Architecture

- The public `/` route is the short front page (`Landing`) whose main button opens the guest dashboard at `/try`; sign-in/sign-up lives at `/auth`, and signed-in users (or old `?checkout=` returns) go straight to `/app`; the Coming Soon page and the archived Nov 2026 sign-in front page (`ArchivedAuthNov2026`) are kept unrouted so either can be restored quickly.
- Stock prices come from two FMP keys selected per request — the personal key only for the owner's own sign-in arriving from the Lovable preview, the commercial key for everyone else and the public site — because the personal plan is personal-use only and must never serve other people; cached quotes and dividends are therefore stored per key (`stock_cache.source`) so data fetched under one plan can't display under the other.
- Commercial closing prices use one shared bulk CSV download per completed New York trading date, saved in the background as batched per-ticker rows (`fmp_eod_prices`) and marked complete only after every batch lands, with a service-only atomic four-hour retry lease, reads of only the requested tickers, and per-ticker EOD fallback whenever the snapshot can't be read or claimed; this avoids repeated restricted bulk downloads and oversized single writes, and keeps unfinished session prices out of portfolios. Company details reuse commercial cached quotes, never the profile's live price. Personal requests never use the bulk snapshot.
- Stock-data request validation lives in its function-local request module so regression tests exercise the deployed schema; keep-alive pings allow omitted or empty tickers while data actions require a nonempty array.
- Alternative eligibility rules (maximum price age, maximum plausible yield) live in one shared module used by every suggestion path (default matches, per-underperformer alternatives, optimizer), so a retired or bad-priced stock can't slip in through any one of them; each stock carries the date of its price from either feed.
- The pool of stocks checked for yield-target matches is the built-in market list plus a named high-yield list in one data module; a listed stock is shown only while its live data passes the stability and eligibility tests, so the list never needs pruning when a company cuts or stops paying.
- Full access (unmasked names, share counts, broker tools) is decided only in `usePaidFeatures`: admins, active subscribers, and anyone inside a free month — a signed-in person's month is a `free_trials` row created solely by the `start_free_trial` database function (one per person, can't be backdated over 30 days, refused for card-free starts after the cutoff), a guest's month is a start date in browser storage. The trial length and cutoff live in `src/lib/freeTrial.ts` and are repeated in that function and in `create-checkout` (which defers the first charge to the free month's end, or adds a card trial when none was used), so all three change together.
- Terms page wording lives in `src/content/termsContent.ts`; the downloadable Terms PDF is rebuilt from it with `python3 scripts/terms-pdf/build_terms_pdf.py` (Privacy pages carried over from the existing PDF), so the page and PDF never drift apart — rebuild the PDF whenever the wording changes.
- Terms agreements are versioned by `termsVersion` in `src/content/termsContent.ts` and recorded only through the `accept_terms` database function (`terms_acceptances`, server-stamped time); `TermsUpdateGate` on signed-in pages blocks use until the current version is agreed, so bump the version whenever the wording materially changes.
- Subscription cancel/undo goes through the `manage-subscription` function (Stripe `cancel_at_period_end`), never a client-side table write, so access runs to the paid period's end and the webhook stays the source of truth.
